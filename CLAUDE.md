# RYFT platform — instructions for Claude Code (VS Code)

You are the **platform agent** for RYFT, working in VS Code with a terminal. The iOS app
is built by a separate agent in Xcode under `../app`; you never edit files there.

## What this folder is
Go services (`backend/cmd/{ingest,scoring,api}` + later `notify`, `coach`), Postgres via
Supabase (local: docker compose or Podman), RabbitMQ (`deploy/rabbitmq`: operators,
cluster, generated topology; D97, it replaced NATS JetStream, D102),
kustomize manifests in
`deploy/k8s` (`base/` + overlays: default, `vault`, `overlays/eks`, `overlays/local-postgres`),
Terraform for the EKS cluster in `infra/aws` and for Vault (namespace per service,
Kubernetes auth, KV, generated VSO manifests) in `infra/vault`, scripts in `scripts/`, and
the website `web/` (ryftapp.de: a static Next.js site with the legal texts, the AASA and
its own nginx image; D107). Read `docs/STATUS.md`, `docs/DECISIONS.md`,
`docs/ARCHITECTURE.md` and `docs/API.md` before changing anything; add a `D<n>` entry to `DECISIONS.md` for every judgement call. The
roadmap is `../ROADMAP.md`; the user pastes one milestone per session.

## Rules
- Go only, stdlib `net/http`, `pgx`, `amqp091-go`; add a dependency only when it clearly
  pays for itself. Env-only config. `slog` JSON logs. Migrations are numbered SQL files in
  `backend/internal/db/migrations/` — never edit an applied one, add a new one.
- Every scoring/insight/behavior rule is a pure function in `internal/scoring` (or a
  sibling package) with a test that pins the calibration. If a constant moves, say why in
  the commit message and `docs/SCORING.md`.
- `docs/API.md` is the contract with the app: additive changes only, JSON examples for
  every shape, a changelog entry per change. Never rename or remove a field in v1.
- Verification before every commit: `cd backend && go vet ./... && go test ./...`, then
  `make smoke` (local apikey mode) and, when `SUPABASE_*` env is set, `make smoke-supabase`.
  When `web/` changed: `make web-test web-build` and `make web-e2e`.
- Git is the only way anything reaches `ryft-prod-euc1`: Argo CD syncs `deploy/argocd/apps`
  (app of apps, D94/D95), and CI promotes images by a PR that pins `overlays/eks` (D96).
  `make k8s-apply-eks` is break-glass only. Never `kubectl apply` against production
  yourself; prepare the commit and the exact commands, then stop. Keep the manifests
  kustomize-only and `make k8s-validate` green (it also checks `deploy/argocd`).
- **Argo CD manages workloads only.** Cluster add-ons (ALB controller, Traefik,
  cert-manager, ExternalDNS, VSO, Argo CD itself) stay Helm releases in
  `infra/aws/kubernetes`; nothing has two owners. The exception is the RabbitMQ
  operators (vendored in `deploy/rabbitmq/operators`, project `ryft-operators`, D97).
  A new workload unit is a file in `deploy/argocd/apps` with a sync wave.
- The broker's topology is Go (`internal/events/amqpbus/topology.go`); after a change run
  `go run ./cmd/rabbitmq-topology` and commit both outputs. Every event goes through the
  outbox (D101), and every handler must stay idempotent (D100), with a test.
- New services get a Deployment, Service, NetworkPolicy rules, probes, resources,
  `/metrics`, and an entry in `docs/OBSERVABILITY.md`.
- Terraform in `infra/aws` and `infra/vault` is the user's; never run `apply`/`destroy`
  yourself — print the plan command and stop. Never touch `terraform.tfstate`. Files
  under `deploy/k8s/overlays/vault-namespaces/` are generated by `infra/vault`; do not edit.
- Never commit secrets. `deploy/k8s/secrets.yaml` and `.env` are git-ignored.
- End each session with `docs/STATUS.md` (done / open / exact deploy commands) and a
  commit per milestone.

## web/
The site for ryftapp.de: pages, legal texts (`content/legal`), the AASA and the nginx image.
Its rules are in `web/CLAUDE.md` (Claude Code loads it inside `web/`); read it before
touching `web/`. The brand rule applies to `web/**`, to the built output and to every commit
message in the repository: `make hooks` once per clone installs `.githooks`, CI checks it
too. Tokens, the Swift-licence snapshot and the AASA test read the app at `../app`
(`RYFT_APP_DIR`). Targets: `make web-install web-test web-build web-e2e web-image web-serve
web-tokens`. The merge ships the site: CI builds the image and promotes it (details in the CI
docs). A privacy text and `PRIVACY_POLICY_VERSION` change in the same PR. On an untrusted PR
checkout, commit with `git -c core.hooksPath=/dev/null` (tracked hooks run the PR's code).
