# RYFT platform — instructions for Claude Code (VS Code)

You are the **platform agent** for RYFT, working in VS Code with a terminal. The iOS app
is built by a separate agent in Xcode under `../app`; you never edit files there.

## What this folder is
Go services (`backend/cmd/{ingest,scoring,api}` + later `notify`, `coach`), Postgres via
Supabase (local: docker compose or Podman), Pub/Sub for events (a topic per key, push to the
services, D218; locally the emulator, `deploy/pubsub-emulator`), the Cloud Run templates in
`deploy/run` (rendered from `deploy/run/config.env`, applied by `deploy.yml`, D223), Terraform
for GCP in `infra/gcp` (HCP org `ryft-lab`, workspace `ryft-gcp`), scripts in `scripts/`, and
the website `web/` (ryftlab.de: a static Next.js export with the legal texts and the AASA,
served by Firebase Hosting in the project `ryftlab-site`; D107, D233). Read `docs/STATUS.md`, `docs/DECISIONS.md`,
`docs/ARCHITECTURE.md` and `docs/API.md` before changing anything; add a `D<n>` entry to `DECISIONS.md` for every judgement call. The
roadmap is `../ROADMAP.md`; the user pastes one milestone per session.

## Rules
- Go only, stdlib `net/http`, `pgx`, Pub/Sub over REST on the stdlib; add a dependency only when it clearly
  pays for itself. Env-only config. `slog` JSON logs. Migrations are numbered SQL files in
  `backend/internal/db/migrations/` — never edit an applied one, add a new one.
- Every scoring/insight/behavior rule is a pure function in `internal/scoring` (or a
  sibling package) with a test that pins the calibration. If a constant moves, say why in
  the commit message and `docs/SCORING.md`.
- `docs/API.md` is the contract with the app: additive changes only, JSON examples for
  every shape, a changelog entry per change. Never rename or remove a field in v1.
- Verification before every commit: `cd backend && go vet ./... && go test ./...`, then
  `make smoke` (local apikey mode) and, when `SUPABASE_*` env is set, `make smoke-supabase`.
  When `web/` changed: `make web-test web-build` and `make web-e2e`.
- Git is the only way anything reaches production: `deploy.yml` deploys main to Cloud Run and the
  site to Firebase Hosting (D223, D233). Never deploy to production by hand (no `gcloud run deploy`,
  no `firebase deploy`); prepare the commit and the exact commands, then stop. Keep
  `make cloudrun-check` green (CI's `manifests` job runs it). The EKS cluster, Argo CD, Vault and
  RabbitMQ are gone (D3, D246).
- The Pub/Sub topology is Go (`internal/events/pubsub/topology.go`); after a change run
  `go run ./cmd/pubsub-topology` (it writes `infra/gcp/pubsub.auto.tfvars.json` and
  `deploy/pubsub-emulator/init.sh`) and commit both outputs. Every event goes through the
  outbox (D101), and every handler must stay idempotent (D100), with a test.
- New services get a Cloud Run template in `deploy/run` (its own service account, ingress,
  limits, probes, secrets pinned by version), its rows in `scripts/check_cloudrun.py`, its account
  and accessors in `infra/gcp`, `/metrics` (local compose; not served on Cloud Run, D224), and an
  entry in `docs/OBSERVABILITY.md`.
- Terraform in `infra/gcp` is the user's; never run `apply`/`destroy` yourself — print the
  plan command and stop. Never touch `terraform.tfstate`.
- Never commit secrets. `.env`, `terraform.tfvars` and `secrets.yaml` are git-ignored.
- End each session with `docs/STATUS.md` (done / open / exact deploy commands) and a
  commit per milestone.

## web/
The site for ryftlab.de: pages, legal texts (`content/legal`), the AASA and the Firebase Hosting
config (`firebase.json`, generated by the build from `scripts/lib/hosting.mjs`).
Its rules are in `web/CLAUDE.md` (Claude Code loads it inside `web/`); read it before touching
`web/`. The brand rule applies to `web/**`, to the built output and to every commit message in
the repository: `make hooks` once per clone installs `.githooks`, CI checks it too. With the
hooks installed every commit needs Node and python3 (they fail closed without either). Tokens, the
Swift-licence snapshot and the AASA test read the app at `../app` (`RYFT_APP_DIR`). Targets:
`make web-install web-test web-build web-e2e web-hosting web-tokens` (`web-e2e` runs against the
pinned Hosting emulator). The merge ships
the site once the repository variable `SITE_DEPLOY` is `on`: `deploy.yml`'s `site` job deploys it
and checks ryftlab.de live (`docs/OPERATIONS.md` → GCP → Deploy, roll back, rotate → The site). A privacy text and
`PRIVACY_POLICY_VERSION` change in the same PR. On an untrusted PR checkout, commit or merge
with `git -c core.hooksPath=/dev/null` (tracked hooks run the PR's code).
