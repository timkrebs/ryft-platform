# RYFT platform

Daily Recovery, Strain and Sleep scores from any watch or ring that writes to Apple Health,
through an iOS app and Go microservices on Google Cloud Run.

Read [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) first — it explains the data
flow, the schema and the scoring model. The HTTP contract with the app is
[`docs/API.md`](docs/API.md); operations (the GCP runbook: deploys, rollbacks, rotation, dead letters) are in
[`docs/OPERATIONS.md`](docs/OPERATIONS.md), metrics in
[`docs/OBSERVABILITY.md`](docs/OBSERVABILITY.md), what is done and how to deploy in
[`docs/STATUS.md`](docs/STATUS.md), and judgement calls in
[`docs/DECISIONS.md`](docs/DECISIONS.md).

```
backend/      Go module: cmd/{api,ingest,scoring,notify,migrate,pubsub-topology}, internal/{scoring,insights,store,db,events,httpx,metrics,model,config,…}
deploy/run/   Cloud Run: the templates of the four services and the job migrate, config.env (deploy.yml renders and applies them)
deploy/pubsub-emulator/   init.sh, the topology on compose's Pub/Sub emulator (generated by cmd/pubsub-topology)
infra/gcp/    Terraform: IAM, secrets, Pub/Sub, Scheduler, Artifact Registry, DNS, logs, monitoring, the edge (the user applies it)
web/          ryftlab.de: static Next.js site, legal texts, AASA, on Firebase Hosting (web/CLAUDE.md, make web-*)
../app/          SwiftUI app (HealthKit sync, Today / Trends / Settings)
scripts/      synth.py (fake Health data), smoke.sh (end-to-end test), print_days.py, cloudrun_render.py, check_cloudrun.py
docker-compose.yml   local stack: Postgres, the Pub/Sub emulator and a ticker, the services
```

## 1. Backend locally

```bash
cd backend && go mod tidy && go test ./...     # tidy once: go.sum is generated on your machine
cd .. && make up                               # Postgres + the Pub/Sub emulator + ingest(:8081) scoring api(:8082) notify
make smoke                                     # synthetic 10 days through the whole pipeline + API contract checks
```

`make smoke` prints a table like:

```
day          recovery  strain  sleep%  need  actual    hrv   rhr  resp  calibrating
2026-10-14         73       0      83   570     471   57.6  49.7  15.1  False
2026-10-15         33    15.0     84   550     463   47.1  51.2  14.6  False
```

Config is env-only: `DATABASE_URL` (the service's own role; for `migrate` the schema owner,
plus `DB_PASSWORD_INGEST|SCORING|API|NOTIFY`), `GCP_PROJECT` with `PUBSUB_EMULATOR_HOST` and `ALLOW_INSECURE_PUSH=true` (compose) or `PUBSUB_ENDPOINT`, `PUSH_AUDIENCE`, `PUSH_SA_EMAIL` and `PUSH_SA_ID` (Cloud Run), `PORT`, `DB_MAX_CONNS`, `LOG_LEVEL`, and for ingest/api
`AUTH_MODE` with `SUPABASE_PROJECT_REF` (production, Supabase tokens) or `API_KEY` +
`ALLOW_INSECURE_APIKEY_AUTH=true` (compose; bearer `API_KEY` or `API_KEY:<uuid>`).
What each means and which combinations are refused: `backend/internal/config`.
Supabase setup: [`docs/SUPABASE.md`](docs/SUPABASE.md).

## 2. Production (GCP)

Cloud Run in europe-west1, project `ryftlab-prod`; nothing is deployed by hand. A merge to `main`
is the deploy (`deploy.yml`, CI below), and the Terraform in [`infra/gcp`](infra/gcp/README.md) is
the user's to apply.

```bash
make cloudrun-check              # deploy/run against its rules (scripts/check_cloudrun.py), as CI's manifests job
make smoke-prod                  # the deploy's smoke against api.ryftlab.de and ingest.ryftlab.de: SUPABASE_URL/ANON_KEY + the smoke user
make smoke-supabase              # with SUPABASE_URL/ANON_KEY + a dedicated test user; writes synthetic days
```

The runbook, from the bootstrap to rollbacks, rotation and the stop line:
[`docs/OPERATIONS.md`](docs/OPERATIONS.md) → GCP.

## CI

`.github/workflows/ci.yml` checks every pull request, every push to `main` and every manual run:
`go vet`, `go test -race`, `golangci-lint` (config: `.golangci.yml`), `govulncheck` and Trivy,
`make cloudrun-check`, `make up && make smoke` on Docker, Terraform, the site's checks, and the site
against the Firebase Hosting emulator (`web-e2e`). Its `ci-ok` job is the required check. It builds no
image to deploy and opens no pull request (since C1). `.github/workflows/deploy.yml` deploys `main`:
after `ci-ok` is green on the commit, it builds, scans and pushes the five images to Artifact Registry
and rolls them out on Cloud Run, and it ships `web/` to Firebase Hosting (`SITE_DEPLOY`).
`docs/OPERATIONS.md` → GCP → **Deploy, roll back, rotate** has the details.
Locally: `make test`, `cd backend && golangci-lint run`, `make cloudrun-check`.

## 3. iOS app

1. On the iPhone: Garmin Connect → More → Settings → **Apple Health** → allow everything.
2. `cd ../app && xcodegen generate && open Ryft.xcodeproj` (or create an empty iOS App
   named *RYFT* in Xcode and drag the `../app/Ryft` folder in). Set your team, make
   sure the target has the **HealthKit** capability with *Background Delivery* and
   **Background Modes → Background fetch**. `Info.plist` and `Ryft.entitlements`
   are included.
3. Run on a real device (HealthKit does nothing in the simulator). Accept the Health
   prompt, open Settings in the app, enter the API URL and API key, tap *Save & test*,
   then *Sync now*. The first sync uploads 90 days; after that only deltas.
4. Scores need ~7 nights before `calibrating` turns off and the baselines are yours.

## Adding a sample type or a metric

1. `backend/internal/model/sync.go` → add the `Sample*` constant.
2. `../app/Ryft/Health/HealthKitManager.swift` → add a `QuantitySpec`.
3. Use it in `internal/scoring/compute.go`; pin the behaviour in `algorithms_test.go`.
